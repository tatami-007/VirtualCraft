# VirtualCraft Tools — Python Edition

Complete Python rewrite of the 13 Java helper tools that used to live in `tools/`. Five Python files
replace 13 Java files (~110 KB) at roughly 76% of the line count, with full pixel-level
regression verification.

The Java sources are preserved under `tools/java_legacy/` as reference / rollback. Generated PNGs are pixel-identical.

---

## 1. `gui_texture_generator.py`  — GUI atlas generator

```powershell
# Generate all 5 GUI textures
python tools\python\gui_texture_generator.py

# Only one
python tools\python\gui_texture_generator.py --only electric_ball_generator

# Regression: verify Python output matches what's on disk (no write)
python tools\python\gui_texture_generator.py --diff
```

Available `--only` names: `pow_miner`, `electric_ball_generator`, `electric_condenser`, `side_config_menu`, `icons`.

`--diff` exits 0 on full match, 1 on any pixel difference, with the first differing pixel reported for debugging.

Pair with `notebook_playground.ipynb` for the fast tweak-and-preview loop (`%autoreload 2` picks up source edits without kernel restart).

## 2. `asset_texture_generator.py`  — item & block textures

```powershell
# Generate all 7 active textures (4 items + 3 cube_all blocks)
python tools\python\asset_texture_generator.py

# Only one
python tools\python\asset_texture_generator.py --only mining_surveyor

# Regression check
python tools\python\asset_texture_generator.py --diff
```

`--only` choices: 7 active + 2 LEGACY (`wireless_transfer_upgrade_card`, `wireless_power_tower`).

The 2 LEGACY generators stay callable but are excluded from the default run because:
- `wireless_transfer_upgrade_card` — item retired from the project (no PNG on disk)
- `wireless_power_tower` — replaced by a hand-drawn 32×32 PNG; the Java 16×16 procedural version would silently overwrite the artist's work

Hand-drawn items (`electric_ingot`, `electric_absorber`, `electric_absorber_on`, `electric_ball`) are skipped — they're authored manually and the Java code only kept the procedural references for reference, not output.

## 3. `preview_tools.py`  — visual preview / annotation

Subcommand-based CLI mirroring 7 separate Java tools:

```powershell
python tools\python\preview_tools.py reference        # AE2-CS sample sheet
python tools\python\preview_tools.py assets           # 12 generated VirtualCraft assets at 8× zoom
python tools\python\preview_tools.py arrow_sprite     # Crop electric_condenser progress arrow
python tools\python\preview_tools.py cells out.png 0,7 1,7    # Crop arbitrary 16×16 icon cells
python tools\python\preview_tools.py on_bg in.png out.png 2 CBCCD4   # Alpha-blend on solid bg + zoom
python tools\python\preview_tools.py sprite_v_fill    # Crop the vertical FE-fill sprite
python tools\python\preview_tools.py annotated        # icons.png with 16×16 grid + section labels
```

All preview PNGs land in `tools/previews/` (the Java tools wrote to `tools/` root — the new layout keeps the root clean).

Pixel-level alpha blending matches Java's `Math.round(c*a + bg*(1-a))` formula exactly. Mixed sprite sizes (16×16 + 32×32) are auto-scaled to fit the grid cell, just like Java's `g.drawImage(src, 0, 0, CELL, CELL, null)` with NEAREST hint.

Text rendering uses Pillow + `Consolas` (Windows) / DejaVu Sans Mono fallback. Visual layout matches Java but exact font metrics may differ by 1–2 px — these are previews for human inspection, not pixel-comparable artifacts.

## 5. `verify_tools.py`  — regression tests (CI-friendly)

```powershell
python tools\python\verify_tools.py icons    # Verify icons.png copy cells + retired cells empty
python tools\python\verify_tools.py vfill    # Verify 16×64 vertical FE-fill matches design table
python tools\python\verify_tools.py vfill --quiet    # Skip per-row pixel grid + histogram
```

Both subcommands exit 0 on full pass, 1 on any failure — wire into your CI / pre-commit hook to catch icon sheet regressions automatically.

> **Note**: Java's `VerifyIcons.java` and `VerifyVFill.java` baselines are stale (their expected tables haven't been updated since GuiTextureGenerator v20.7 unified all four borders to `WINDOW_HIGH #F2F2F2` and retired the LINK icon). The Python ports refresh those tables to match v20.7 reality, so they actually run green against the current `icons.png`. Comments in `verify_tools.py` document each baseline change.

## Architecture & code reuse

The 5 Python files share infrastructure to avoid duplication:

```
gui_texture_generator.py
├── _c(0xRRGGBB)        Java new Color(...).getRGB() equivalent → (r, g, b, 255)
├── _java_round(x)      Java Math.round semantics (half-up, NOT Python banker's)
└── class Primitives    canvas / fill_rect / clear_rect / copy_rect / lerp_color

asset_texture_generator.py
└── from gui_texture_generator import _c, Primitives  ← reuses the lot
```

`preview_tools.py`, `analyzer_tools.py`, `verify_tools.py` all use numpy + PIL directly without going through the generator pipeline.

### Java → Python parity guarantees

| Concern | Java | Python equivalent |
|---|---|---|
| Color literal | `new Color(0xRRGGBB)` (alpha=0xFF) | `_c(0xRRGGBB)` → `(r, g, b, 255)` |
| Canvas init | `BufferedImage.TYPE_INT_ARGB` (0x00000000) | `np.zeros((h, w, 4), uint8)` |
| `fillRect` OOB | silently clipped | numpy slice with `max(0,...)` / `min(W,...)` |
| `setRGB(getRGB)` copy | OVERWRITES alpha | numpy slice assignment (NOT PIL `paste` — that blends!) |
| `Math.round(float)` | half-away-from-zero | `_java_round` = `math.floor(x + 0.5)` (NOT Python `round` banker's) |
| PNG load | `ImageIO.read` → ARGB | `Image.open(...).convert('RGBA')` |
| PNG save | `ImageIO.write(..., "png", ...)` | `Image.fromarray(arr, 'RGBA').save(...)` |
| Bresenham circle | int err, 8-symmetric | identical algorithm in `Helpers.draw_circle` |
| Alpha blend on bg | `Math.round(c*a + bg*(1-a))` | `np.floor(blended + 0.5).astype(uint8)` |

All 12 procedurally generated PNGs (5 GUI + 7 asset) verified pixel-identical to Java output via `--diff`.

## When to use which

| Scenario | Tool |
|---|---|
| Tweak a single color and see it instantly | **Notebook** + `%autoreload 2` |
| Batch regenerate all GUI textures | `python tools\python\gui_texture_generator.py` |
| Batch regenerate all item/block textures | `python tools\python\asset_texture_generator.py` |
| Verify generator refactor didn't break pixels | `--diff` flag on either generator |
| Visually review a specific sprite at 12× zoom | `python tools\python\preview_tools.py cells` / `arrow_sprite` |
| Calibrate a color from a real AE2 reference | `python tools\python\analyzer_tools.py color_sample` |
| CI / pre-commit regression test | `python tools\python\verify_tools.py icons && python tools\python\verify_tools.py vfill` |
| Long-running compile-once codebase | `tools/java_legacy/*.java` — still works, untouched |

The Python tools and Java tools write to **identical** disk paths under `src/main/resources/...`. You can switch back and forth freely; whichever one you ran last wins. `--diff` always tells you whether they agree.
